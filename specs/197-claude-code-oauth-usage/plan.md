# Implementation Plan: Claude Code OAuth Token Usage & Limits

**Branch**: `197-claude-code-oauth-usage` | **Date**: 2026-03-26 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/specs/197-claude-code-oauth-usage/spec.md`

## Summary

Replace the broken "Anthropic OAuth Rate Limits" widget with a new "Claude Code" tab on the Usage page. The primary data source is **response headers** (`anthropic-ratelimit-unified-*`), parsed on every proxy response — extended to capture the missing `7d_sonnet` utilization and `anthropic-organization-id`. The Usage API (`/api/oauth/usage`) serves only as a **cold-start fallback** when the store is empty and the user enters the tab (due to aggressive 429 rate limiting per GitHub issues #31021, #31637). The new tab displays per-token progress bars for 5h session, 7d weekly, and 7d sonnet-only utilization, matching Anthropic's native "Plan usage limits" UI.

## Technical Context

**Language/Version**: Go 1.26
**Primary Dependencies**: chi/v5 (router), templ + templUI + Tailwind CSS v4 (UI), pgx/v5 (PostgreSQL)
**Storage**: PostgreSQL (org ID persistence), in-memory (usage state cache)
**Testing**: `go test` + `testify`, `httptest.NewServer` for mock upstream
**Target Platform**: Linux server (Docker/Kubernetes)
**Performance Goals**: Response header parsing adds zero latency (synchronous, no external calls); Usage API fallback completes within 5s
**Constraints**: Usage API has ~5 request limit per token per session before permanent 429; no Retry-After header
**Scale/Scope**: 1-10 OAuth tokens per deployment (typical)

**Structure Decision**: Follows existing TianjiLLM patterns. Response header parsing extended in-place (ratelimit_store.go). New OAuthUsageStore is a separate store from RateLimitStore — it holds the unified data model for the new Claude Code tab, populated from both response headers and Usage API fallback.

## Data Flow

```
Path 1: Proxy Response (primary, every request)
  Anthropic response → ParseAnthropicOAuthRateLimitHeaders() [EXTENDED]
    → existing RateLimitStore.Set()          (retained for Discord alerts + throttle)
    → NEW: OAuthUsageStore.SetFromHeaders()  (for Claude Code tab)
    → NEW: DB.UpsertOAuthTokenMetadata()     (org ID persistence, async)

Path 2: Cold-Start Fallback (rare, only when store empty + user enters tab)
  Client GET /ui/api/claude-code-usage
    → store empty? → FetchOAuthUsage(token) → api.anthropic.com/api/oauth/usage
    → store result (or return "no data yet" on 429/error)
    → return JSON

Path 3: UI Rendering
  Client enters Claude Code tab → HTMX hx-get /ui/usage/tab?tab=claude-code
    → loadClaudeCodeData() reads OAuthUsageStore + DB org IDs
    → render templ component with progress bars
```
