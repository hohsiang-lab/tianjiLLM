# Implementation Plan: Encrypted OpenAI Subscription Credential Persistence

**Branch**: `HO-1176-openai-subscription-credential-persistence` | **Date**: 2026-05-06 | **Spec**: [spec.md](spec.md)  
**Input**: Feature specification from `/specs/1176-openai-subscription-credential-persistence/spec.md`

## Summary

Add backend-only encrypted persistence for OpenAI subscription OAuth credentials by reusing existing `CredentialTable`: encrypted token bundle in `credential_value`, safe metadata in `credential_info`, typed `openai_subscription` helpers, redacted list/info responses, and sqlc update support for token refresh rotation.

## Technical Context

**Language/Version**: Go module in TianjiLLM  
**Primary Dependencies**: Existing `golang.org/x/crypto/nacl/secretbox`, `encoding/json`, `time`, `github.com/jackc/pgx/v5` through sqlc, existing `testify` tests  
**Storage**: Existing PostgreSQL `CredentialTable` with `credential_type`, encrypted `credential_value`, and `credential_info JSONB`  
**Testing**: `go test` unit/handler tests plus sqlc generation check; no real OpenAI network  
**Target Platform**: Linux server / Docker / Kubernetes  
**Performance Goals**: Credential create/update is admin/callback path only; encryption and JSON marshaling are negligible  
**Constraints**: No production implementation until Linear moves to In Progress; no secrets in list/info responses; no handwritten DB queries  
**Scale/Scope**: One row per OpenAI subscription account/credential; refresh path updates an existing row

## Data Flow

```text
OpenAI callback/refresh slice receives token response
  -> build OpenAISubscriptionTokenBundle{
       access_token, refresh_token, expires_at, account_id
     }
  -> build OpenAISubscriptionCredentialInfo{
       email, scopes, status, last_refresh_at, last_error, disabled_reason
     }
  -> json.Marshal(secret bundle)
  -> auth.Encrypt(plaintext, masterKey)
  -> db.CreateCredential or db.UpdateCredentialValueAndInfo
       credential_type = "openai_subscription"
       credential_value = encrypted JSON
       credential_info = safe metadata JSON

Management API
  -> db.ListCredentials / db.GetCredential
  -> redact credential_value
  -> include credential_info as JSON metadata
```

## No Schema Migration Decision

No schema migration is planned for HO-1176 because current `internal/db/schema/004_credentials.up.sql` already provides:

- `credential_type TEXT NOT NULL DEFAULT 'api_key'`
- `credential_value TEXT NOT NULL`
- `credential_info JSONB NOT NULL DEFAULT '{}'`

Implementation must add migration/rollback only if tests expose a real missing schema invariant. If no migration is added, the PR must mention "schema unchanged" explicitly.

## Plan Review

- **Repo evidence**: `internal/proxy/handler/credentials.go` already encrypts credential create/update with `auth.Encrypt`, but list currently returns DB rows directly and info omits metadata; HO-1176 must add shared redaction/metadata response mapping.
- **Repo evidence**: `internal/db/schema/004_credentials.up.sql` already has `credential_type`, encrypted `credential_value`, and JSONB `credential_info`, so no migration is planned.
- **OpenAI official docs**: Codex authentication docs state ChatGPT sign-in caches credentials locally, refreshes tokens automatically, and treats `auth.json` as password-equivalent because it contains access tokens.
- **OpenAI source**: `openai/codex` persists token data with `access_token`, `refresh_token`, `account_id`, updates `last_refresh`, and persists a new `refresh_token` when one is returned.
- **pkg.go.dev secretbox**: NaCl SecretBox encrypts and authenticates small messages; random 24-byte nonces are acceptable with negligible collision risk. Existing `auth.Encrypt` already prepends nonce and base64url encodes ciphertext.
- **Context7 pgx**: pgx JSONB codec supports JSONB encoding/decoding through marshal/unmarshal and sqlc maps the repo's `credential_info JSONB` to `[]byte`; passing JSON bytes matches existing generated code.
- **grep-app**: `/Users/n0rmanc/.cargo/bin/grep-app-cli` failed with a transport content-type error, so no public GitHub pattern was used beyond direct official `openai/codex` source inspection.

## Phase 1: Tests First

Write the tests listed in `## Failing Tests` before production changes. Initial expected failure mode: missing OpenAI subscription helper functions, unsafe list/info response shape, and missing sqlc update query.

## Phase 2: Typed Payloads and Validation

Add typed structs/helpers for:

- `OpenAISubscriptionCredentialType = "openai_subscription"`
- `OpenAISubscriptionTokenBundle`
- `OpenAISubscriptionCredentialInfo`
- validation that rejects empty required secret fields
- metadata sanitizer that rejects secret fields in `credential_info`

## Phase 3: Persistence and Rotation

Implement create/update helpers:

- create path uses existing `CreateCredential`
- refresh path uses new sqlc `UpdateCredentialValueAndInfo` query
- refresh update computes `expires_at` from token response, preserves old refresh token when response omits one, and overwrites it when response includes one
- failure metadata update does not rewrite `credential_value` unless a new secret bundle is explicitly provided

## Phase 4: Redacted API Responses

Replace direct DB row response mapping with a redacted credential response object:

- include `credential_id`, `credential_name`, `credential_type`, `organization_id`, timestamps, and parsed `credential_info`
- omit `credential_value`
- never include token field names from secret payload

## Phase 5: Verify

- Run `make generate` after SQL changes.
- Run targeted tests from Verification Command.
- Run broader handler tests if targeted tests pass.
- Confirm `git diff --name-only origin/main...HEAD` contains only HO-1176 spec artifacts during Todo planning, and later only HO-1176 implementation files.

## Risk Register

| Risk | Mitigation |
|------|------------|
| Existing list endpoint currently returns full DB rows | Add redaction tests before changing mapper; make redacted mapper shared by list/info. |
| Metadata accidentally carries secret fields | Add sanitizer/test that rejects token field names in `credential_info`. |
| Rotated refresh token not persisted | Add test comparing decrypted old vs new payload; update encrypted value and metadata in one helper call. |
| Empty master key weakens at-rest protection | Existing auth behavior derives a key from configured master key; this issue should not silently change key policy, but tests should use a non-empty master key. |
| Concurrency during refresh can overwrite newer tokens | Keep this issue scoped to correct persistence semantics; distributed refresh locking belongs to later refresh scheduler/routing issue unless Linear expands scope. |
